# P1 Part 2 — Login + Device Limit Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development.
> - The `test-writer` agent writes every `*_test.dart`, first and failing. A project hook enforces this.
> - An `implementer` makes the tests pass and commits.
> - A reviewer checks each task, and an Opus final review covers the whole branch.
>
> Steps use checkbox syntax.

**Goal:** On staging, a student can sign up and sign in with email and password. The app registers the device on every sign-in or session restore. A third device is sent to the device-limit gate. A device revoked elsewhere is signed out within 60 s. A router guard keeps signed-out users on the auth screens.

**Architecture:**
- The feature lives in `apps/client/lib/features/auth/` with data, domain and presentation layers (ADR-007).
- **Data:** thin wrappers over `supabase_flutter`. RPC calls go through an injected `RpcCaller` function so tests need no Postgrest builders. The device id is a random 32-hex string kept in a Hive box.
- **Domain:** repository interfaces return `Result<T>`, plus a sealed `DeviceRegistration`.
- **Presentation:**
  - one app-wide `AuthCubit`, registered as a singleton (ruled exception, see Global Constraints);
  - four screens: sign-in, sign-up, check-inbox and the device gate.
- **Router:** `createRouter` gains an optional `AuthCubit?`. When it is given, a go_router `redirect` and a `refreshListenable` built from the Cubit stream enforce the guard. When it is null, there is no guard, which keeps the existing router tests valid.
- **Errors:** shared mappers in `lib/core/errors/` turn `AuthException` and `PostgrestException` into `AppError` codes.

**Tech Stack:** Flutter 3.44.1, flutter_bloc 9, bloc_test 10, mocktail 1, go_router 18, supabase_flutter 2.18, hive_ce 2.20, get_it 9. No new packages.

**Spec:** `docs/superpowers/specs/2026-10-16-p1-login-design.md` (1f9bac7), with the deltas below.

## Spec deltas (from planning, 2026-10-16)
1. **No backend change.** S-11 at sign-in uses `register_device`'s `limit_reached` payload: `devices[{id, platform, label, last_seen_at}]` and `changes_left`. The "manage devices" page (not at sign-in) is deferred, and so is a "list my devices" RPC. RLS already allows `select` on own `devices` rows if that page is built later.
2. **Exact RPC contract** (`supabase/migrations/20261009000000_auth04_device_limit.sql`):
   - **`register_device`** returns either `{"status":"ok","device_id"}` or `{"status":"limit_reached","devices":[…],"changes_left":int}`. It raises `not_authenticated` or `invalid_input`. The fingerprint must match `^[A-Za-z0-9_-]{16,128}$`, the platform must be one of `web|android|ios`, and the label is at most 80 characters.
   - **`remove_device`** returns `{"changes_left":int}`. It raises `forbidden` (not yours, or already revoked) or `device_limit` (no changes left).
   - **`device_status`** returns `'active'`, `'revoked'` or `'unknown'` as text.
   - Exceptions reach the client as `PostgrestException.message` equal to the code.
3. **The device is registered on every sign-in and on session restore**, which also refreshes `last_seen_at`. `device_status` is used only for the 60-second and app-resume revocation checks:
   - `'revoked'` → sign out with reason `deviceRemoved`;
   - `'unknown'` → register again;
   - `'active'` → do nothing.
4. **The App Check Edge Function `register-device` (docs/07) is not used yet.** The client calls the RPC directly, and the Edge Function arrives with App Check enforcement later.
5. **Client-side auth codes** are added to `docs/07` §9 as a separate "client-only (GoTrue / transport)" list:
   - `invalid_credentials`, `email_not_confirmed`, `email_taken`, `weak_password` and `network`;
   - `rate_limited` reuses the existing code.
6. **Hidden in this part** (out of scope): "Continue with Google", "Forgot password?" and "Contact support". The no-changes-left gate shows "Contact your teacher" text instead.

## Global Constraints
- CLAUDE.md A.1–A.7 and B.1–B.9:
  - layers are never skipped;
  - `domain/` imports no Flutter or Supabase;
  - Cubits depend only on repository interfaces;
  - `isClosed` is checked before emitting after an `await`;
  - subscriptions and timers are cancelled in `close()`;
  - no codegen, so hand-written `fromJson`, sealed classes and exhaustive `switch`;
  - all DI happens in `lib/core/di/injection.dart`;
  - go_router only;
  - controllers and focus nodes live in `initState`/`dispose`;
  - `BlocBuilder`/`BlocSelector` wrap the smallest subtree.
- **Ruled DI exception:** `AuthCubit` is `registerLazySingleton`, not a factory, because it is app-wide session state read by the router. A comment in `injection.dart` says so.
- **No timers or real clock in logic.** `AuthCubit` takes a `Stream<void> Function(Duration) ticker`. The default is `Stream.periodic`; tests pass a controller.
- **English UI copy, verbatim from the design** (listed in Task 4). Raw exception text is never shown.
- Sizes and colours come from Booklet tokens and the theme. The card max-width of 400 becomes a `BookletSize.authCard` token.
- Never log or print tokens, passwords or emails (A.6).
- Test names start with `P1-2:`. Viewports are 360×800 and 1280×800. No network and no real timers.
- Never commit `.codex/` or `.impeccable/`; use `git commit -- <paths>`.

## Review Focus
1. **Double sign-in tap or racing ticks.** Overlapping `register_device` calls must not emit stale states. Use an in-flight guard and check `isClosed` after every `await`. → Task 3 test.
2. **The device check after sign-out.** The ticker must be cancelled on sign-out and on `close()`, with no emits after close. → Task 3 test.
3. **Email-confirmation path.** With confirmation on, `signUp` returns a null session. The app must show "Check your inbox", not "signed in" and not an error. Signing in before confirming maps `email_not_confirmed` to a clear message. → Tasks 2 and 3 tests.
4. **Gate with `changes_left = 0`.** Remove is disabled, the copy says "No changes left this month.", and sign-out still works. If the server reports `device_limit` because of a race, show the same state. → Tasks 3 and 4 tests.
5. **Guard loops.** Each redirect must be idempotent: no redirect loop between `/sign-in` and `/`, and `/gallery` stays reachable while signed out outside prod. → Task 5 test.

## Task 1 — Error mapping, domain, device id and info
**Produces:** `ErrorCodes`, the three mappers, all domain types, `DeviceIdStore`, `DeviceInfo`.
- **Mappers:**
  - `AuthException.code` maps to:
    - `invalid_credentials` → `invalidCredentials`;
    - `email_not_confirmed` → `emailNotConfirmed`;
    - `user_already_exists` / `email_exists` → `emailTaken`;
    - `weak_password` → `weakPassword`;
    - `over_request_rate_limit` / `over_email_send_rate_limit` → `rateLimited`;
    - a null code with an `AuthRetryableFetchException` → `network`;
    - anything else → `internal`.
  - `PostgrestException.message` that is a known §9 code maps to that code; anything else maps to `internal`.
  - Keep the original message in `AppError.message` for logs only.
- **`DeviceIdStore(Box<String> box)`:**
  - The id is 32 lowercase hex characters from `Random.secure()`. It is generated once and then read back unchanged.
  - The Box is opened in `main.dart` (Task 5) with `Hive.openBox<String>('device')`.
- **`DeviceInfo`:**
  - Platform comes from `kIsWeb`, otherwise `defaultTargetPlatform`.
  - The web label parses `package:web` `navigator.userAgent` (already a dependency) into "Browser on OS", for example Chrome/Edge/Firefox/Safari on Windows/macOS/Android/iOS/Linux, falling back to "Web browser".
  - Mobile labels are "Android app" / "iOS app".
  - Use a conditional import (`if (dart.library.js_interop)`) so the VM tests compile. The label is truncated to 80 characters.

## Task 3 — AuthCubit and DI
Behaviour:
- **`start()`:**
  - no current user → `SignedOut()`;
  - otherwise `Busy`, then `register()`:
    - `Allowed` → `SignedIn` and start the ticker;
    - `LimitReached` → `DeviceGate`;
    - failure → `SignedOut(error)`.
- **`signIn`:**
  - `Busy`, then `repo.signIn`, then `register()`, with the same branches as `start()`;
  - an auth failure → `SignedOut(error)`;
  - ignored while `Busy` (in-flight guard).
- **`signUp`:**
  - `confirmationSent` → `ConfirmationSent(email)`;
  - `signedIn` → `register` flow;
  - failure → `SignedOut(error)`.
- **`removeDevice(id)`:**
  - `DeviceGate(removing: true)`, then `remove`:
    - ok → `register()`;
    - `device_limit` failure → `DeviceGate(changesLeft: 0, error)`;
    - other failure → `DeviceGate(error)`.
- **`checkDevice()`:** only when `SignedIn`.
  - `revoked` → `signOut(deviceRemoved)`;
  - `unknown` → `register()` flow;
  - `active` or a failure → no change (a transient network error must not sign out).
- **`signOut(reason)`:** cancel the ticker, `repo.signOut()` with the error ignored for UX, then `SignedOut(reason)`.
- **`ErrorReporter`:** `setUser(user.id)` on `SignedIn`, `clearUser()` on sign-out. Never send the email.
- **`close()`:** cancel the ticker subscription.
- **DI:** register in `injection.dart`:
  - `DeviceIdStore` (with the opened box);
  - `DeviceInfo`;
  - both data sources;
  - both repositories;
  - `AuthCubit` as `registerLazySingleton`, with the ruled-exception comment.

  `configureDependencies` gains a `required Box<String> deviceBox` parameter.
- [ ] test-writer: `bloc_test` cases for each method and branch above, plus Review Focus 1 (a double `signIn` makes one repository call) and Review Focus 2 (after `signOut`/`close`, a ticker event makes no repository call and no emit). Use a `StreamController<void>` ticker. These tests should FAIL first.
