# Homework (PRC-02, PRC-05, LRN-01/02, GRD-03, ANL-02) — design + plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or superpowers:executing-plans. In this repo, tasks go to Codex via `codex-delegate` (tests first); the router runs gates and commits.
> The user skipped the question round for this week's push ("ابدأ واعمل اللي تقترحه"). Every decision below is the **router's call** unless the PRD/docs already fix it.

**Goal:** Each student gets one auto-drawn homework set per topic between Practice and Quiz: answer at their own pace with autosave, mark for review, submit once, then see a report with keys and explanations. The quiz requires the homework to be submitted.

**Architecture:** Server-side homework reuses the quiz attempt machinery. That means `attempts` with `kind='homework'`, `attempt_questions`, `attempt_answers`, a kind-aware `save_answer` / `submit_attempt` / `get_attempt_review`, and a new `start_homework`. The client adds `features/homework`, cloned from the shape of `features/quiz` and using `QuestionView`'s existing `HomeworkMode`. One shared attempt-review screen serves the homework report now and the quiz review later (S-23).

**Spec sources:** `docs/02-prd.md` PRC-02 (L91), PRC-05, LRN-01/02 (L65-66), GRD-03, ANL-02; `docs/07` §2 (steps), §3 (draw), §4 (grading); `docs/04` S-20/S-21.

## Decisions

| # | Decision |
|---|----------|
| H1 | Step order is Video → Notes → Practice → **Homework** → Quiz (LRN-01). Homework is available once `practice_count ≥ practice_min`, which is the gate the quiz uses today. The quiz then also needs `homework_submitted_at`, via a new quiz state `homework_needed` and a new error code `homework_needed`. |
| H2 | **Exemptions** (like notes/video): the homework step is skipped and never blocks the quiz when (a) the topic has 0 published practice questions, or (b) the student already passed the quiz. |
| H3 | **No deadline, no timer, one attempt per student per topic, single submission** (PRC-02). `time_limit_s` stays null for homework. Answers can be edited until submit. |
| H4 | **Draw** at `start_homework`, frozen into `attempt_questions`: published practice-pool questions of the topic, **not answered in practice by this student first**, then the least recently seen, random within each group, limit `settings.homework_size` (20). If the pool is smaller, draw what exists. The E/M/H blueprint and subtopic coverage (`docs/07` §3) are deferred, like the quiz spiral. Draw count 0 → the step is skipped (H2a). |
| H5 | Homework answers do **not** change `practice_count`. The drawn questions are written to `question_exposure` at draw time, like the quiz does. |
| H6 | `save_answer` accepts `kind in ('quiz','homework')`. The deadline/expiry checks apply only to the quiz. Mark-for-review works for homework, since `HomeworkMode` already has `onMark`. |
| H7 | `submit_attempt` branches on the kind. For homework it grades every answer via the existing grader (unanswered = incorrect) and stores `meta.report` (`score_raw`, `score_total`, `score_pct`). It sets `topic_progress.homework_attempt_id/homework_score/homework_submitted_at`. No pass/fail, no cooldown, no unlock. Resubmitting a submitted attempt returns the same report (idempotent). **No keys in its response** (rule 1). |
| H8 | `get_attempt_review` accepts homework. **For homework, `keys_visible` = submitted**, because the questions come from the practice pool, whose keys practice already reveals (PRC-02: "full review with explanations"). The quiz rule stays unchanged. `pass_mark`/`passed` are null for homework. |
| H9 | `get_topic` gains `homework: {state, attempt_id?, score_pct?, total?}` with `state ∈ locked_by_practice | available | in_progress | submitted | skipped`, and the quiz object can carry state `homework_needed`. |
| H10 | **Client report** (S-21): after submit, the screen shows the score ("14 / 20 · 70%") and a per-question list (my answer, the correct answer, the explanation, using `MathText`). It is built as a shared `AttemptReviewScreen` in `lib/shared/` + `features/attempt_review/`, opened from the topic page ("View report"). A quiz attempt opens the same screen, honoring `keys_visible` (this closes the "attempt-review UI" quiz follow-up). |
| H11 | Leaving homework mid-way is fine. The topic page shows "Continue homework (8 / 20 answered)". |
| H12 | Migration `20261102100000_p1_homework.sql`, pgTAP `43_homework.test.sql`. Error code `homework_needed` is added to `docs/07` §9, the EF mirror (`supabase/functions/api/app.ts` `ERROR_CODES`) and client `ErrorCodes`. |

## Non-goals
Teacher-assigned homework, deadlines, retakes, a teacher completion matrix (ANL-05, after launch), the E/M/H blueprint, mastery updates beyond what the grader already does.

## Anti-goals
- A key or explanation reaching the client before submit (rule 1). pgTAP proves that `start_homework` and `save_answer` responses carry no `key`/`explanation`.
- A student starting a second homework attempt for the same topic, including two concurrent `start_homework` calls (use an advisory lock or a unique partial index on `(user_id, topic_id) where kind='homework'`).
- The quiz becoming reachable without submitted homework when the topic has practice questions.

## Global Constraints
CLAUDE.md rules 1–10, A, B. SQL starts from `supabase/templates/` and follows `docs/16` §2. Redefine each function from its **latest** migration definition (grep `supabase/migrations` for the last `create or replace function public.<name>`). No `$$` inside function bodies. Explicit grants. pgTAP: add `reset role;` before privileged steps after `tests.clear_authentication()`. Write non-ASCII in Dart strings as `·` etc. No new pub packages.

## Review Focus
1. Two tabs starting homework at once produce one attempt (pgTAP with two calls in a row; the second returns the same attempt).
2. A topic whose practice pool is smaller than 20 draws all of it; a pool of 0 skips the step, and the quiz is available.
3. A student who passed the quiz before this migration is not blocked (exemption H2b).
4. Autosave after submit is refused (`invalid_input`) and does not change the report.
5. Resuming in another browser shows the saved answers and marks.
