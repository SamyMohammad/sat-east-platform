# F-4 AppShell Implementation Plan

> **For agentic workers:** Test-writer creates tests first; a shell implementer owns the shell widgets; parent owns router/tokens/integration; a code-reviewer reviews the final result. Preserve preceding uncommitted components.

**Goal:** Render the booklet application container with five working navigation destinations at phone/tablet/laptop widths and a separate focus-mode container.

**Architecture:** Shell widgets receive selected index, content and callbacks without go_router, Cubits or business logic. `core/router/app_router.dart` alone connects the shell to `StatefulShellRoute.indexedStack`. Native Material navigation retains keyboard/semantics; a persistent content subtree preserves state when the layout changes.

**Tech Stack:** Existing Flutter 3.44.1 / Dart 3.12.1 / go_router 18.0.2; no new dependencies.

**Spec:** Parent design-system plan AppShell section; `docs/superpowers/specs/2026-10-13-f4-design-system-questionview-design.md` §2; `docs/design/claude-design-export/App Shell.dc.html`.

## Global Constraints

- Continue user-selected branch `feat/F-4-components-inputs`; no commit/push/deploy.
- Approved existing direction is implemented, not redesigned. Shared UI goes in `shared/widgets/app_shell/` under current AGENTS.md.
- Destinations: Home, Courses, Skills, Mock exams, Profile; no feature logic or fake scores.
- Existing breakpoint mapping: width≤600 compact, 600<width<1024 medium, width≥1024 expanded; test both exact boundaries.
- Compact uses NavigationBar, medium NavigationRail, expanded permanent NavigationDrawer.
- Base dimensions from export: rail80, sidebar256, headers56/64/72, monograms32/40, bottom navigation80. Expand where necessary for 2× text rather than clip/shrink it.
- Content margins16/24/32. Shell does not cap all content at readingColumn; each future feature owns its reading layout.
- Native navigation labels and filled selected icons provide non-color selection cues.
- Header brand: AE on compact/medium, full Abdelrahman Elmenshawy and SAT & EST Math on expanded.
- Notifications action is optional and only enabled by a caller callback; no unfinished notification route or fake notification data.
- Native NavigationRail.scrollable supports short-height viewports; sidebar also scrolls.
- FocusModeScaffold renders supplied body/header/footer only, no navigation. Exam timer/tools/exit confirmation belong to QuestionView/features, not the shell.
- English UI; no new implementation details in placeholder copy. Existing Home placeholder remains compatible with F-1 test.
- No feature Cubit is introduced for purely local responsive rendering, keyboard focus or navigation callbacks.

## Review Focus

1. Selection/deep links match all five routes at every breakpoint.
2. Resizing does not dispose body state or move the selected destination unexpectedly.
3. Long labels/brand at 2× and short height remain readable and scrollable.
4. Skip link appears on keyboard focus, activates content focus, and owned FocusNodes dispose safely.
5. Focus mode contains no destination navigation and leaves exit/timer decisions to the caller.
