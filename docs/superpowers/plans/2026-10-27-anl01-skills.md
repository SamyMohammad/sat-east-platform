# ANL-01 Skills Screen and Mastery Implementation Plan

> **For agentic workers:** Implement task by task; Codex via `codex-delegate` (tests first), Sonnet `implementer` fallback. Claude runs the gates and commits. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Server-computed skill mastery from every graded answer, a Skills screen at `/skills`, and a per-skill breakdown on the quiz result.

**Architecture:** Triggers on `attempt_answers` (practice/review first try) and `attempts` (quiz/homework submit) call one `private.apply_mastery` that updates `skill_mastery` and a new daily history table; a security-definer `get_my_skills` RPC returns aggregates only. The client adds a `skills` feature (data/domain/presentation, Cubit) and extends `QuizReport`.

**Tech Stack:** Supabase Postgres + pgTAP; Flutter, flutter_bloc, get_it, go_router, supabase_flutter. No new packages.

**Spec:** `docs/superpowers/specs/2026-10-27-anl01-skills-design.md`

## Global Constraints

- Rule 1: no question ids, stems, answers, explanations or keys in `get_my_skills`; `private.question_keys` is never read by new code.
- Rule 2/5: all mastery math server-side; every number from `settings`: `mastery_alpha` 0.15, `mastery_weights` `{"practice":0.5,"homework":1.0,"quiz":1.2,"mock":1.5}`, `mastery_difficulty` `{"E":0.8,"M":1.0,"H":1.2}`, `mastery_start` 50, `mastery_weak_below` 50, `mastery_min_attempts` 5, `mastery_trend_min_answers` 10; strong threshold = existing `pass_mark` (75).
- Rule 3/9/10: new table with RLS + pgTAP; every public RPC `revoke ... from public, anon` + `grant execute ... to authenticated`; SQL from `supabase/templates/`, `docs/16` §2 checklist.
- Bands: `thin` if attempts < min_attempts, else `weak` < 50, `strong` ≥ pass_mark, else `building`. Copy: "Weak", "Building", "Strong", "Not enough answers yet".
- Client: CLAUDE.md A/B rules, `DESIGN.md` tokens, icon + word for every band, every animation via `AppMotion.resolve`, English sentence case.
- Error codes from `docs/07` §9 only (`not_authenticated`, `not_enrolled`, `access_expired`, `invalid_input`, `internal`).
- Gates: `scripts/db-test.ps1` (repo root); from `apps/client/`: `dart format --output=none --set-exit-if-changed .`, `flutter analyze --fatal-infos`, `flutter test --exclude-tags golden`, `flutter test test/goldens --tags golden`.

## Review Focus

1. **Questions with no skill tags** (taxonomy not loaded): mastery untouched, `summary.solved/total` still correct, screen shows summary + topics and the "no skills yet" copy instead of an empty list. Tests: Task 3 `no_tags_summary_only`, Task 6 `no_skills_state`.
2. **Student enrolled in two courses:** `get_my_skills(A)` never returns skills/topics that only appear in course B. Test: Task 3 `other_course_excluded`.
3. **Expired access:** `get_my_skills` raises `access_expired`; screen shows the mapped error copy with retry. Tests: Task 3 `expired_access_raises`, Task 6 `access_expired_copy`.
4. **Double submit / auto-submit at time-up:** a quiz moving to `submitted` updates mastery exactly once, also via the timer path in `submit_attempt`. Test: Task 2 `quiz_submit_counts_once`.
5. **One week of data:** trend with fewer than 2 points renders the thin copy, not a single dot or a flat line. Tests: Task 3 `trend_thin_under_min_answers`, Task 6 `trend_single_point_is_thin`.

### Task 3: `get_my_skills` RPC

**Files:**
- Create: `supabase/migrations/20261103100200_anl01_get_my_skills.sql`
- Create: `supabase/tests/46_get_my_skills.test.sql`

**Interfaces:**
- Consumes: `skill_mastery`, `skill_mastery_daily`, settings (Task 1).
- Produces: `public.get_my_skills(p_course_id uuid) returns jsonb` — exact shape:
  `{"summary":{"solved":int,"total":int,"graded_answers":int},"skills":[{"code","name","domain","mastery":num|null,"attempts":int,"band":"weak|building|strong|thin"}],"weak":[{"code","name","mastery","topic_id","topic_title"}],"trend":[{"week_start":"YYYY-MM-DD","mastery":num}],"topics":[{"topic_id","title","unit_title","solved":int,"total":int,"level":"weak|building|strong|thin"}]}`.
  `solved` = distinct published questions of the course answered correctly in any graded answer; `total` = published questions of the course; skills = skills tagged on the course's published questions (sorted domain, name); weak = up to 3 lowest with band `weak`, target topic = the course topic with most practice-pool questions for that skill; trend = weekly mean of the student's daily rows for those skills, last 8 weeks, `[]` when `graded_answers < mastery_trend_min_answers` or fewer than 2 weeks; topic level = band of mean mastery of skills on that topic's questions (`thin` when their summed attempts < min_attempts).

- [ ] **Step 1: Write failing tests**: `not_authenticated_raises`, `not_enrolled_raises`, `expired_access_raises`, `shape_keys_exact` (no key named like `question*`, `stem*`, `answer*`, `key*`, `explanation*` anywhere in the output), `bands_from_settings` (49→weak, 50→building, 75→strong, 4 attempts→thin), `weak_top3_with_topic_target`, `trend_thin_under_min_answers`, `trend_weekly_mean`, `solved_counts_distinct_correct`, `no_tags_summary_only`, `other_course_excluded`, `grants_authenticated_only`.
