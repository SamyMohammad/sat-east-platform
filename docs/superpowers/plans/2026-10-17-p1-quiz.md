# P1 part 5 — Quiz + unlock Implementation Plan

> **For agentic workers:** executed by Codex via `codex-delegate` (one brief per task, router reviews gates + diff, router commits by path). Steps use `- [ ]`.
> On approval this file is copied to `docs/superpowers/plans/2026-10-17-p1-quiz.md` and committed on `feat/P1-quiz`.

**Goal:** Enrolled student goes topic page → 10 practice → timed 12-question quiz (autosaved, resumable, server clock) → pass ≥ `pass_mark` opens the next topic; fail starts a 12 h cooldown.

**Architecture:** One shared grader `private.grade_answer`; quiz state machine `private.quiz_state` + lazy expiry `private.expire_quiz`; public RPCs `get_topic`, `start_quiz`, `save_answer`, `submit_attempt`. Unlock is implicit via `private.topic_states` (completed = `quiz_passed_at`). Client features `topic` (page) and `quiz` (cubit with server-offset clock, ticker, ordered autosave; result page); practice moves under the topic.

**Tech stack:** Postgres/plpgsql + pgTAP, Flutter, flutter_bloc, get_it, go_router, supabase_flutter, bloc_test + mocktail.

**Spec:** `docs/superpowers/specs/2026-10-17-p1-quiz-design.md` (approved). Tier **L**.

## Context
Parts 1–4 merged (#26 #27 #29 #30). This closes the P1 vertical slice: login → course → topic → practice → quiz → unlock on staging.

- RPCs from `supabase/templates/rpc.sql`: `security definer`, `search_path = ''`, qualified names, `auth.uid()` first, revoke `public, anon` + grant `authenticated`; private helpers revoked from `public, anon, authenticated`.
- Settings (new, `on conflict do nothing`): `quiz_size` 12, `quiz_time_per_q_s` 90, `quiz_warn_s` 300; existing `pass_mark` 75, `cooldown_h` 12, `practice_min` 10, `save_grace_s` 30. No literals for these anywhere.
- No key / explanation / hint / misconception / `is_correct` in any quiz payload before submit; submit report has no keys.
- Lazy expiry runs **before** the access check; in-quiz `save_answer` / manual `submit_attempt` still require access after expiry.
- `15_course_map` and `16_practice` pgTAP files stay unchanged and green.
- Client: no codegen; domain pure; cubits depend on repository interfaces; `isClosed` after awaits; injected `DateTime Function() now` and ticker; cancel ticker in `close()`; copy exact as in spec §2.
- Commit by path only; `.codex/`, `.impeccable/`, `.vscode/` stay untracked. Tests prefixed `PRC-03` / `L-6`.

## Review Focus
1. **Reload mid-quiz** → `start_quiz` resumes same attempt; answers, marks, remaining time restored (T2 pgTAP resume; T5 cubit resume test).
2. **Clock skew** (device clock 10 min off) → remaining time follows server deadline via offset (T5 test with skewed `now`).
3. **Time-up while a save is in flight / offline** → exactly one submit, after the in-flight save settles; a `deadline_passed` save triggers submit (T5).
4. **Pass at exactly 75 %** (9/12) passes; 8/12 fails (T2).
5. **Abandoned quiz past deadline** → graded at deadline by the next `get_topic`, even if access has since expired (T2).

### Task 5: QuizCubit
**Files:** `lib/features/quiz/presentation/cubit/quiz_cubit.dart`, `quiz_state.dart`; `lib/core/time/ticker.dart` — `typedef Ticker = Stream<void> Function(Duration period);` default `(p) => Stream<void>.periodic(p)` (reuse/move the auth device-check ticker if one exists); DI factory `QuizCubit(getIt<QuizRepository>(), DateTime.now, defaultTicker)`.
- States: `QuizLoading` · `QuizFailed(AppError)` · `QuizRunning(session, index, answers, marked, remaining, timerHidden, saveError?, submitting)` · `QuizSubmitted(QuizReport)`.
- Methods: `start(topicId)`, `select(label)`, `sprChanged(text)`, `toggleMark()`, `goTo(i)`, `next()`, `prev()`, `toggleTimer()`, `submit()`. Time-up handled internally.
- Rules: offset = `serverNow − now()` at start; remaining = `deadline − (now() + offset)` each tick (1 s); ≤ 0 → submit once. Per-question time accumulates while a question is shown and is sent with its save. Saves: one in flight, coalesce to latest per question, `clientSeq` strictly increasing; failure → `saveError`, retry after 2 s then 5 s then 10 s; `deadline_passed` → submit. `submit()` waits for the in-flight save, then submits once; failure keeps the state with an error and allows retry.
- [ ] Tests (fake ticker StreamController, fixed + skewed `now`): start create; resume restores answers/marks and remaining from server; each start error; select → save with seq 1, two quick changes → seqs ordered, only latest sent after in-flight; save failure → saveError then retry succeeds; stale ignored; countdown; skewed clock; time-up submits exactly once even with a pending save; manual submit; submit failure + retry; close cancels ticker. RED → GREEN. Commit `feat(P1): quiz cubit`.
