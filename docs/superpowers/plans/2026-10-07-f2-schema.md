## Context
Row 2b of the Phase 0 checklist (`docs/15` §1). Every later story reads these tables. The brainstorm (2026-10-07) agreed: schema only, tables locked until row 3; FK deletes cascade for user data and restrict for content; `updated_at` triggers; a sign-up trigger that creates `profiles`; two migration files; 9 settings defaults.

## Global Constraints
- Every SQL file follows `supabase/templates/` and the checklist in `supabase/templates/README.md` (CLAUDE.md rule 10).
- No `grant` to `anon` or `authenticated` on any table in this row (locked until row 3).
- `security definer` functions: `set search_path = ''`, fully-qualified names, live in `private`.
- Seed uses `on conflict (key) do nothing`.
- Tests: one behaviour per assertion, file header `-- F-2 / NFR-08 — …`, `begin; … rollback;`, like `supabase/tests/00_*.test.sql`.
- Every commit message ends with a blank line, then `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. In the commit commands below, the message is the first line; add the trailer when running them.
- Tests designed to change later. Update them; never delete them to make a build pass:
  - `04_schema_locked` "no privileges yet" is replaced by row 3, when grants and policies land.
  - `03_schema_tables` `tables_are` list is extended by every story that adds a table.

## Review Focus
1. Real sign-up runs as `supabase_auth_admin`, not `postgres` → the profile must still be created (Task 2 test).
2. Phone sign-up with no e-mail and no name → `full_name` falls back to `'Student'`, sign-up never fails (Task 2 test).
3. A client puts `"role":"teacher"` in sign-up metadata → profile is still `student` (Task 2 test).
4. Re-running the seed after the teacher changed `pass_mark` → the teacher's value stays (Task 3 test).
5. An answer for a question that is not in the attempt's frozen draw → rejected by FK (Task 2 test).

## Small additions beyond the spec (user-approved 2026-10-07; written into `docs/06` in Task 1)
- Authorship references (`courses.owner_id`, `activation_codes.created_by/redeemed_by`, `topic_progress.unlocked_by`, `audit_log.actor`) → `on delete set null` (deleting a teacher must not delete courses).
- `orders.user_id` → `restrict`: an account with payment records cannot be hard-deleted.
- `attempt_answers (attempt_id, question_id)` → FK to `attempt_questions` (answers only for the frozen draw).
- `device_changes` gets an identity PK; `question_exposure(user_id)` index skipped (the PK already leads with `user_id`).
- `service_role` gets table/sequence grants on `public` (hardening Layer 3 revoked its defaults; Edge Functions need them).
- Expected advisor notices until row 3: "RLS enabled, no policy"; also INFO "unindexed foreign keys" (indexes are added by the story whose query needs them).

```sql
-- updated_at (docs/06 conventions)
create function private.set_updated_at()
returns trigger
language plpgsql
set search_path = ''
as $$
begin
  new.updated_at := now();
  return new;
end;
$$;

create trigger set_updated_at before update on public.questions
  for each row execute function private.set_updated_at();
create trigger set_updated_at before update on private.question_keys
  for each row execute function private.set_updated_at();
create trigger set_updated_at before update on public.video_progress
  for each row execute function private.set_updated_at();
create trigger set_updated_at before update on public.skill_mastery
  for each row execute function private.set_updated_at();
create trigger set_updated_at before update on public.settings
  for each row execute function private.set_updated_at();

-- Sign-up → profile (docs/06 conventions). role is never read from client metadata.
create function private.handle_new_user()
returns trigger
language plpgsql
security definer
set search_path = ''
as $$
begin
  insert into public.profiles (id, full_name)
  values (
    new.id,
    coalesce(
      nullif(trim(new.raw_user_meta_data ->> 'full_name'), ''),
      nullif(split_part(coalesce(new.email, ''), '@', 1), ''),
      'Student'
    )
  );
  return new;
end;
$$;

create trigger on_auth_user_created after insert on auth.users
  for each row execute function private.handle_new_user();
```
